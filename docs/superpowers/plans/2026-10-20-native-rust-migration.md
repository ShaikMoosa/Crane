# Crane Native Rust Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. The user previously selected native/inline execution. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Crane's Tauri/web interface with a native Rust egui/eframe + wgpu application while preserving its existing library, writing workflows, transfers, recovery, and Windows installation.

**Architecture:** Extract the existing Rust behavior into domain, application, storage, and platform crates, then compose a native desktop shell around typed commands and committed query state. Keep the old application working through thin adapters until a native parity and recovery gate permits cutover. Develop against isolated data; production data and the old installer remain available for recovery.

**Tech Stack:** Rust 1.99.1; Cargo workspace; serde/serde_json; egui/eframe and wgpu; rfd native dialogs; atomic versioned JSON; Windows MSVC/NSIS. No cloud service or Node build pipeline.

**Spec:** `docs/superpowers/specs/2026-10-20-native-rust-migration-design.md`, approved 2026-10-20.

**Execution status:** Planning only. Review this plan before starting Task 1. Local planning branch: `codex/native-rust-migration-plan`; product baseline: `6770f1292f5d741cedffff3ec99c84221b6a179f`.

## Global Constraints

- Rust, egui/eframe, and wgpu are the selected target. Domain/application have no UI, OS, filesystem, network, identity-provider, or billing-provider dependency.
- No new native application code introduces Tauri, Electron, a webview, JS/TS UI, a Node runtime/build dependency, remote scripts/fonts, or required services. The legacy shell is temporary and excluded from the root workspace until removal.
- Windows is the release acceptance target. No macOS/Linux readiness is claimed by compilation alone.
- Keep `schemaVersion: 1` and `backupVersion: 1` for the migration.
- Preserve IDs, Unicode text, exact note bodies, timestamps, tag arrays, flags, note order, and unknown supported-version JSON fields during unchanged round trips.
- Keep 500 UTF-8 bytes per title, 2 MiB per body, timestamps at most `8_640_000_000_000_000`, unique non-empty IDs, 64 MiB aggregate Markdown selection, and 256 MiB per backup input/output.
- Preview builds use an isolated test data root and cannot silently fall back to the production root. Do not inspect or copy the user's actual note bodies into tests.
- Persist a validated candidate before publishing committed memory; save failures retain editor drafts and expose Retry. Creation of onboarding data is allowed only when the library is genuinely absent.
- One mutation worker, bounded queues, coalesced pending saves, and per-note draft revisions prevent stale save results from discarding newer typing.
- Transfers flush the latest draft and reject conflicting mutations. Restore cancellation works before commit; cancellation is disabled once replacement starts. Confirmation expires after five monotonic minutes and is revoked on cancellation, new inspection, use, and exit.
- Preserve Crane's existing design intent and all shipped note/transfer features. Browser-specific conveniences such as spellcheck require a native feasibility check before claiming parity.
- Release upgrade replaces the old installed binary, refuses a running legacy process, retains the existing data root, and creates a validated pre-migration backup. Uninstall preserves user data.
- Final delivery has no Tauri/WebView2 or JavaScript/Node build requirement. Docker, accounts, billing, sync, MCP, collaboration, and hosted APIs are outside this plan.
- Use focused modules and the existing original Crane identity/assets. Do not copy Bear, Opensidian, PhotoCraft, or third-party product assets or prose.

## Review Focus

1. A normal save completing after newer typing must acknowledge only its own draft revision; selecting another note or closing must not discard the newer draft. Task 6 tests delayed results, queue saturation, and failed-close saves.
2. An existing empty, Unicode, extended-field, corrupt, inaccessible, or future-version library must be distinguished correctly; none may be silently replaced with onboarding data. Tasks 1, 2, and 9 test these startup/compatibility classes.
3. Two shells or a stale restore confirmation must not overwrite intervening user work. Tasks 5 and 9 test revision-bound confirmation, revocation/expiry, exclusive ownership, and legacy-process cutover refusal.
4. Windows Unicode-equivalent export names, normalized overwrite targets, reparse points, and write failures must never destroy unrelated files or publish a partial export. Tasks 2 and 5 test exclusive reservation and transactional publication.
5. A successful headless test or build does not prove a usable native editor, GPU, dialog, or installer. Tasks 7 and 9 record real Windows IME, clipboard, keyboard/screen-reader, DPI, GPU, and installer evidence before Task 10 removes the fallback.

## File ownership and contract map

- `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`: root workspace, shared dependency resolution, and tested toolchain. Add a workspace member only when its source exists; explicitly exclude `src-tauri`.
- `crates/domain/src/{lib,model,error,query,markdown,backup,preview}.rs`: pure models/validation/querying, interchange codecs, and safe Markdown document representation.
- `crates/application/src/{lib,commands,error,ports,library,restore}.rs`: typed command/result types, ports, committed state, and transaction/confirmation orchestration.
- `crates/storage/src/{lib,repository,atomic,bounded,transfers,settings}.rs`: JSON repository, bounded IO, atomic file/directory publication, and settings persistence.
- `crates/platform/src/{lib,paths,atomic_replace,instance,dialogs,fonts,links,environment}.rs`: narrow Windows/OS integrations. Implement application ports here only after Task 3 defines them.
- `apps/desktop/src/{main,lib,app,worker,draft,view_state,theme,settings,transfers}.rs` and `apps/desktop/src/views/{mod,library,note_list,editor,preview,restore}.rs`: shell composition, state machines, task results, and native widgets.
- Each crate owns `tests/`; share fixtures under `fixtures/compat/v1/` and support fakes under the owning crate's `tests/support/mod.rs`. No general-purpose testkit crate.
- `scripts/{check-layers,check-native-release,build-windows,smoke-windows}.ps1`, `packaging/windows/{crane.nsi,app.manifest,README.md}`, `.github/workflows/native-windows.yml`: checks and native delivery. Store only test evidence, metadata, and checksums under ignored `artifacts/`.
- `docs/migration/{compatibility,behavior-parity,windows-acceptance}.md`: current-versus-native evidence and explicit gates. `AGENTS.md`, `PRODUCT.md`, `DESIGN.md`, and `README.md` describe the current stage truthfully.

Dependency direction: application -> domain; platform -> application/domain; storage -> application/domain/platform; desktop -> application/domain/storage/platform. Platform never imports storage. Only desktop depends on egui/eframe/winit/wgpu. OS and file IO are absent from domain/application production code; std collection/time value types are permitted, but actual clocks are injected.

## Verification conventions

Run a new behavior regression before production changes and record its intended failure; missing symbols are acceptable at the first introduction of a crate/API. Do not add tests that merely restate documentation or inspect implementation text. Preserve/refactor existing Rust tests rather than rewriting them without need.

After a workspace dependency change, resolve/update the root lock once, inspect the dependency diff, and use `--locked` thereafter. While the excluded legacy package depends on shared crates, update its own lock deliberately as well. Neither lock is hand-edited. Use the installed toolchain; do not install tooling speculatively.

Task commands below run at the repository root unless shown otherwise. After every task, run its named command and the existing tests it affects. Milestone and final gates run the full required checks; do not repeatedly rebuild an unchanged installer between tasks.
